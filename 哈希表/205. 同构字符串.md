# LeetCode 205. 同构字符串

[LeetCode 205. 同构字符串](https://leetcode.cn/problems/isomorphic-strings/description/?envType=study-plan-v2&envId=top-interview-150)
# 前置知识：哈希表

这道题主要会用到哈希表。

在 Python 中，哈希表通常使用 `dict`。

它可以用来记录一种映射关系：

```text
key -> value
````

例如：

```python
mapping = {
    "a": "b",
    "c": "d"
}
```

可以理解为：

```text
a -> b
c -> d
```

而“同构字符串”本质上就是一种映射关系，所以这道题很适合用哈希表来做。

---

# 最开始的理解

一开始看到“同构”，我最先想到的是：

> 只要两个字符串中，各个字符出现的次数能够对应上，是不是就可以了？

比如某个字符在 `s` 中出现一次，另一个字符在 `t` 中也出现一次。

但后来发现，这个理解是不对的。

因为同构并不是单纯比较字符数量，而是要求：

> **两个字符串相同位置上的字符，必须保持稳定的一一映射关系。**

也就是说，重点不只is "how many there are", but also“谁和谁对应”。

---

## 第一个问题：双重 for 循环并不是一一对应

我最开始还想过这样遍历：

```python
for num in s:
    for num_t in t:
```

一开始觉得这样可以让 `s` 和 `t` 进行对应。

但实际上，这种循环的执行方式是：

```text
s 中的第一个字符
    -> 和 t 中所有字符比较

s 中的第二个字符
    -> 再和 t 中所有字符比较
```

也就是说：

```text
s[0] -> t[0], t[1], t[2], ...
s[1] -> t[0], t[1], t[2], ...
```

这并不是题目要求的“一一对应”。

题目真正需要的是：

```text
s[0] <-> t[0]
s[1] <-> t[1]
s[2] <-> t[2]
...
```

由于题目中的 `s` 和 `t` 长度相同，所以可以使用下标 `i` 同时访问两个字符串的相同位置：

```python
for i in range(len(s)):
    num = s[i]
    num_t = t[i]
```

这样才能保证每次比较的都是同一个位置上的两个字符。

---

## 第二个问题：一个哈希表还不够

接下来我的想法是：

用一个哈希表记录：

```text
s 中的字符 -> t 中的字符
```

例如：

```text
e -> a
g -> d
```

如果后面再次遇到 `e`，就检查它是不是仍然对应 `a`。

这个方向本身没错。

但是后来发现还有一个问题：

**映射必须是双向的一一对应。**

也就是说，不仅要保证：

```text
同一个 s 字符不能映射到不同的 t 字符
```

还要保证：

```text
不同的 s 字符不能映射到同一个 t 字符
```

所以不能只检查：

```text
s -> t
```

还需要同时检查：

```text
t -> s
```

因此需要两个哈希表：

```python
s1 = {}
t1 = {}
```

其中：

```text
s1：记录 s -> t
t1：记录 t -> s
```

---

# 最终思路

遍历字符串的每一个位置：

```python
for i in range(len(s)):
    num = s[i]
    num_t = t[i]
```

对于当前的两个字符：

```text
num   = s[i]
num_t = t[i]
```

## 情况 1：双方都还没有建立映射

如果：

```python
num not in s1 and num_t not in t1
```

说明这两个字符之前都没有出现过。

那么可以直接建立双向映射：

```python
s1[num] = num_t
t1[num_t] = num
```

相当于：

```text
num   -> num_t
num_t -> num
```

---

## 情况 2：至少有一方已经出现过

只要有一方已经存在于哈希表中，就不能直接重新建立映射了。

因为这时候原来的映射关系有可能被破坏。

所以需要检查：

```text
s -> t 是否仍然一致
t -> s 是否仍然一致
```

为了防止某个 key 不存在时直接访问导致报错，可以使用：

```python
dict.get(key, 默认值)
```

于是判断可以写成：

```python
if s1.get(num, 0) != num_t or t1.get(num_t, 0) != num:
    return False
```

只要任意一个方向的映射关系不一致，就说明这两个字符串不是同构字符串。

如果整个循环都没有发现冲突，最后：

```python
return True
```

---

# 最终代码

```python
class Solution:
    def isIsomorphic(self, s: str, t: str) -> bool:
        s1 = {}
        t1 = {}

        for i in range(len(s)):
            num = s[i]
            num_t = t[i]

            if num not in s1 and num_t not in t1:
                s1[num] = num_t
                t1[num_t] = num
            else:
                if s1.get(num, 0) != num_t or t1.get(num_t, 0) != num:
                    return False

        return True
```

---
# 优化
把代码从“分情况嵌套判断”再简化一点，核心思路不变，还是 **两个哈希表做双向映射**。

现在这版是：

```python
if num not in s1 and num_t not in t1:
    s1[num] = num_t
    t1[num_t] = num
else:
    if s1.get(num, 0) != num_t or t1.get(num_t, 0) != num:
        return False
```

可以优化成更直接的写法：

```python
if num in s1 and s1[num] != num_t:
    return False

if num_t in t1 and t1[num_t] != num:
    return False

s1[num] = num_t
t1[num_t] = num
```

这样逻辑更直：

* 如果 `s -> t` 已经存在，但对应关系变了，`False`
* 如果 `t -> s` 已经存在，但对应关系变了，`False`
* 如果都没冲突，就把当前映射写进去

完整就是：

```python
class Solution:
    def isIsomorphic(self, s: str, t: str) -> bool:
        s1 = {}
        t1 = {}

        for i in range(len(s)):
            a = s[i]
            b = t[i]

            if a in s1 and s1[a] != b:
                return False

            if b in t1 and t1[b] != a:
                return False

            s1[a] = b
            t1[b] = a

        return True
```

这个优化主要是 **减少嵌套，让条件更清楚**，复杂度并没有变化

# 这道题我踩的几个坑

1. **同构不是比较字符数量是否相同**

   真正需要比较的是字符之间是否保持固定映射关系。

2. **不能使用双重 for 循环进行一一对应**

   双重循环会让 `s` 中一个字符和 `t` 中所有字符比较，而题目要求的是相同下标之间进行对应。

3. **只建立 `s -> t` 的映射还不够**

   同构要求一一对应，所以还要保证 `t -> s` 也成立。

4. **直接访问哈希表可能出现 key 不存在的问题**

   可以使用：

```python
mapping.get(key, 0)
```

避免直接访问不存在的 key 时产生报错。

# 复杂度分析

设字符串长度为 `n`。

只需要遍历一次字符串：

* 时间复杂度：`O(n)`

使用两个哈希表记录字符映射：

* 空间复杂度：`O(n)`

如果考虑字符集大小固定，那么空间复杂度也可以视为 `O(1)`。
